Ingest the slide deck: $ARGUMENTS  (a .pptx or PDF exported from Google Slides, for a dated meeting)

Slides are supplementary. The meeting notes are the primary record, so do not duplicate them.

1. Read the deck. Identify content that is NOT already captured from that meeting's notes: a
   presented figure or diagram, a data table, a literature-framing slide, or a decision shown
   only on a slide.
2. Report what is net-new before writing. If the deck is only talking points already in the
   notes, say so and write nothing.
3. For net-new content:
   - Save figures and diagrams to raw/assets/ with a dated name, e.g.
     2026-05-15-architecture.png, and reference them from the relevant wiki page.
   - File presented data as a comparisons page (status hypothesis if preliminary, reference if
     it comes from a cited paper).
   - File framing or argument as a concept or question page, status hypothesis.
   - Cross-link to that meeting's wiki/log.md entry so the deck and the discussion connect.

Preserve Korean with a short gloss. Never promote anything to finding.
